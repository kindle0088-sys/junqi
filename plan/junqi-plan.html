1. 游戏规则确认

1.1 棋盘结构

标准军棋棋盘，双方对称，中间以河流分隔。每方包含：

  • 兵站（×23）：棋子常规站位点
  • 行营（×5）：安全区，进入后不可被吃
  • 大本营（×2）：军旗的固定位置，进入后不可再移动
  • 铁路线（粗线）：直线可任意距离移动
  • 公路线（细线）：每次只能移动一格
⚠️ 本计划采用二人明棋规则（明棋 = 棋子亮明展开，无需翻棋阶段）
后续可扩展暗棋/翻棋模式。

1.2 棋子体系（每方25枚）

指挥层 · 1~9级

棋子数量等级
司令 🟥19（最高）
军长 🟧18
师长 🟨27
旅长 🟩26
团长 🔵25
营长 🟪24
连长 🟫33
排长 ⬛32
工兵 🔧31（最低）

特殊棋子

棋子数量规则
💣 炸弹2与任何棋子同归于尽
⛰️ 地雷3不可移动，仅工兵可挖
🚩 军旗1不可移动，被吃即输

1.3 核心规则

  • 吃子：高级吃低级，同级同归于尽
  • 炸弹：碰任何子都同归于尽（包括军旗）
  • 地雷：仅工兵能吃；其他子碰雷即死
  • 工兵：铁路线上可任意拐弯"飞行"；可挖地雷
  • 行营：进入后对方不可攻击，行营内每次走1格
  • 大本营：军旗必须放此处；进大本营后不可再移动
  • 铁路：非工兵棋子只能直线移动，不限步数
  • 公路：所有棋子每次只能移动1格

1.4 胜负判定

  1. 吃掉对方 军旗 → 胜
  2. 对方 无棋可走（仅剩地雷+军旗）→ 胜
  3. 对方 认输/超时 → 胜

1.5 初始布局约束

  • 军旗 → 必须放在己方 两个大本营之一
  • 地雷 → 只能放在己方阵地 最后两排（含大本营所在行）
  • 炸弹 → 不放在第一排（可选规则，默认开启限制）
  • 行营 → 初始不可放子

2. 技术架构

选型原则：零框架依赖、学习成本低、可部署到免费托管。
前后端分离，后端 Node.js + WebSocket，前端纯 HTML/CSS/JS + Canvas。

🎨 前端

  • HTML + CSS（单页应用）
  • Canvas 2D 绘制棋盘
  • Socket.IO Client
  • 无需 React/Vue

⚙️ 后端

  • Node.js + Express
  • Socket.IO（WebSocket）
  • 纯内存状态（无需数据库）
  • 单进程即可撑 100+ 对局

2.2 Server 是权威仲裁

所有走子合法性由服务端验证，客户端只负责展示和发送操作请求——防作弊。

4. 网络协议设计

4.1 Socket.IO 事件表

方向事件数据说明
C→Screate_room{ playerName }创建新房间
S→Croom_created{ roomId, players[] }返回房间 ID
C→Sjoin_room{ roomId, playerName }加入已有房间
S→Croom_joined{ roomId, players[], side }确认加入，分配阵营
S→Cgame_start{ board }双方就绪，开始游戏
C→Smake_move{ from, to }走子请求
S→Cmove_result{ success, from, to, captured, board, currentTurn }行动结果广播
S→Cgame_over{ winner, reason }游戏结束
C→Sresign-认输
C→Schat{ message }聊天（可选）

6.2 棋盘视觉设计

  • 采用 2D Canvas 绘制，自顶向下俯视棋盘
  • 铁路线用粗线 + 公路线用细线
  • 行营用菱形标记
  • 大本营用旗帜标记
  • 棋子显示为圆形，内含中文+等级数字
  • 红方在下（近端），蓝方在上（远端）

6.3 交互设计

  1. 点击棋子 → 选中，高亮显示可移动位置
  2. 点击目标位置 → 发送走子请求
  3. 吃子时 → 简短动画效果，显示被吃棋子
  4. 回合切换 → 轮到自己时有视觉提示

7. 分阶段实施路线

1

棋盘渲染 + 棋子布局

前端 完成 Canvas 棋盘绘制：铁路线、公路线、行营、大本营。
静态摆放所有棋子（红蓝双方各25枚），实现基本渲染。

2

单人走子逻辑

前端 后端 实现：
- 棋盘拓扑（位置连接图）
- 走子规则（铁路直线/公路1格）
- 工兵特殊行走（铁路可拐弯）
- 行营/大本营移动限制
先做成单机可走子的 demo。

3

吃子 + 胜负判定

后端 实现完整规则引擎：
- 等级吃子逻辑（含同级同尽）
- 炸弹同归于尽
- 地雷仅工兵可挖
- 军旗被吃/无棋可走判定
此时可做单人 vs AI（简易随机走子）来测试规则。

4

WebSocket 联机对战

后端 实现：
- Room 管理器（创建/加入/列表/退出）
- Socket.IO 事件绑定
- 服务端权威仲裁（所有规则在服务端跑，客户端只展示）
- 回合同步、网络断开处理

5

全流程联调 + 打磨

前端 后端 综合
- 连接全流程（创建房间 → 加入房间 → 开始对局 → 结束）
- 连接状态指示、重连逻辑
- 超时/认输处理
- UI 体验打磨（动画、音效提示、响应式布局）

6

部署上线（可选）

部署 部署到 CloudStudio 或 Vercel + Render 等免费服务，给个链接就能和朋友直接玩。
